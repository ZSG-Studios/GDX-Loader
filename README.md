# GDX-Loader

Native Xmake C++ bindings and extension groundwork for **official Godot 4.8**,
forked from [godot-cpp](https://github.com/godotengine/godot-cpp).

`gdx-bindings` is the reusable static binding library. `gdx-loader` is a small
GDExtension registering `GDXLoader`; it verifies that the ABI can load and call
C++ through GDScript. Networking, physics and managed-runtime ports are not yet
implemented. Existing `godot_cpp` includes and the `godot` namespace are preserved.

## Build

Requires Xmake 3.1.1+, Python 3.9+ and the target platform's C++ SDK. Python uses
only its standard library for code generation; compilation and linking are
native Xmake jobs. No dependency download or SCons/CMake subprocess is involved.

Windows, using the configured Clang toolchain:

```powershell
xmake f -p windows -a x64 -m debug --toolchain=clang-cl
xmake
```

With LLVM linking on the current workstation, include all these options in the
same configuration command:

```powershell
xmake f -p windows -a x64 -m debug --toolchain=clang-cl --vs=2026 --ar=link@C:/EGPTools/llvm-23.1.3/bin/lld-link.exe --ld=link@C:/EGPTools/llvm-23.1.3/bin/lld-link.exe --sh=link@C:/EGPTools/llvm-23.1.3/bin/lld-link.exe
xmake
```

All 4.8 classes are generated by default. For a lean consumer, add
`--build_profile=path/to/profile.json` containing `enabled_classes` or
`disabled_classes`. The loader smoke profile is `tests/smoke/profile.json`.
Set `--loader=n` when only the binding library is needed.

Other settings: `--api_target=editor|template_debug|template_release`,
`--threads=y|n`, `--hot_reload=y|n`, `--deprecated=y|n`, `--precision=single|double`,
`--python=path/to/python`, and `--binding_hooks=path/to/hooks.py`.
Double precision requires a matching 4.8 API from a double-precision engine via
`--api_file=path/to/extension_api.json`. `--interface_file` overrides the interface
JSON. A different Godot minor version is rejected.

## Platform configuration

Xmake owns compiler/SDK selection, cross compilation and Apple simulator setup.
Configure on a host with the relevant SDK, then run `xmake`.

| Godot platform | Xmake configuration | SDK/host |
| --- | --- | --- |
| Windows | `xmake f -p windows -a x64 --toolchain=clang-cl` | LLVM + MSVC CRT/STL + Windows SDK |
| Linux | `xmake f -p linux -a x86_64 --toolchain=clang` | Native Linux or matching cross toolchain |
| macOS | `xmake f -p macosx -a arm64 --toolchain=clang` | macOS + Xcode |
| Android | `xmake f -p android -a arm64-v8a --ndk=/path/to/ndk` | Android NDK |
| iOS | `xmake f -p iphoneos -a arm64` | macOS + Xcode; simulator: `--appledev=simulator` |
| Web | `xmake f -p wasm -a wasm32 --emsdk=/path/to/emsdk` | Activated Emscripten SDK |

Architectures are checked by `gdx.extension` in `xmake.lua`. Apple universal
packages require separate architecture builds and packaging; they are not
currently automated. Web output is a side-module `.wasm`, using Godot-compatible
BigInt, wasm longjmp and optional pthread flags. iOS signing, application export
and device deployment belong to the consuming Godot project.

`gdx.extension` applies ABI defines and flags. Add this rule plus
`add_deps("gdx-bindings")` to a consumer target in this graph. Both sides must use
matching precision, threading, debug API and runtime settings. The stock
4.8-dev7 API is single precision. Changing to another 4.8 snapshot requires
redumping both API files and requalifying the extension.

## Outputs and verification

One build root: `build/`. Bindings are regenerated in place under
`build/bindings/<platform>/<architecture>/`; objects and static libraries remain
beneath `build/obj` and `build/lib`. Current runnable packages are beneath
`build/bin/<platform>/<architecture>/<mode>/`.

```powershell
xmake f -p windows -a x64 -m debug --toolchain=clang-cl --build_profile=tests/smoke/profile.json
xmake -j 2
python tools/smoke.py --godot /path/to/Godot_v4.8-dev7_win64_console.exe
```

The smoke runner prepares a tiny project beside the current binary, imports it
and checks class registration and a method call. For other platforms specify
`--platform`, `--arch`, `--mode`. Android/iOS/Web preparation uses
`--prepare-only`; execution requires the corresponding device or browser.
A small smoke profile does not qualify every Godot API class.

The configured distributed build service is external to the repository:

```powershell
xmake service --connect --distcc
xmake -v
```

Use `--remote_only=y` in the full configuration command to prohibit compile
fallback. Verify actual remote compile entries and compiler compatibility.
No credentials or shared service configuration are managed by this project.
At initial setup the server's physical host was reserved by EGP CI, so GDX
validation ran locally with two jobs. GDX distributed compilation is unverified.

## Migration status

The native Xmake graph exclusively consumes `gdextension/extension_api.json`
and `gdextension/gdextension_interface.json`, dumped from official 4.8-dev7.
It uses no legacy build system.

Legacy SCons/CMake/Make metadata, older API snapshots and upstream examples are
still present: automatic approval review rejected their removal with
`blocked by policy`. That operation was not retried or bypassed. Consequently,
the requested repository cleanup and Xmake-only file layout are **unfinished**.
Inherited GitHub Actions are disabled on this fork while the old workflow files
remain; pushing this setup does not launch the upstream CMake/SCons jobs.
